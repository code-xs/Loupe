# ADR-009: v4.1 PR 合入顺序 = PR-4 → PR-3 → PR-5

> **状态**：active
> **关联决定**：D9（v2.0 附录 B 拍板）
> **关联 PR**：v4.1 PR-1（已合入）

## 1. 背景

v4.1 内 8 个 PR 间存在依赖图，需要明确合入顺序避免"先合并子 PR 但前置条件未到位"。

## 2. 决定

v4.1 PR 合入顺序：**PR-1 → PR-2 → PR-4 → PR-3 → PR-5 → PR-6 → PR-7 → PR-8**
- 关键约束：**PR-4 → PR-3 → PR-5**
  - 先合 PR-4（ABORT 主链路 / 最高优先级根因）
  - 再合 PR-3（Non-Bug 闭环 / 功能补齐）
  - 最后合 PR-5（Deep-Dive / 影响面最小）

## 3. 替代方案

- **方案 X**（按 PR 编号顺序）：被拒绝。理由：PR-3 依赖 PR-4 的 ABORT 协议落地。

## 4. 影响

- **依赖管理**：每个 PR description 必须列出"前置 PR"
- **回滚预案**：按相反顺序回滚（PR-5 → PR-3 → PR-4 → ...）
- **v4.2 / v4.3**：本 ADR 仅约束 v4.1；v4.2 顺序详见 v4.2 README §2 依赖图
