# 隔离诊断模式参考

> 本文件为功能疑难专项子工作流 F4（隔离诊断与对抗）提供控制变量推演的方法论参考。

## 隔离原则

隔离诊断的核心是 **控制变量法**：每次只改变一个条件，观察异常是否消失或改变。
目标是将"多因子复合问题"拆解为"单因子可验证假设"。

## 隔离维度与方法

### 1. Mock 隔离（外部依赖隔离）

**目标**：排除外部依赖（服务端、第三方 SDK、系统服务）的干扰。

**方法**：
- 用 Mock 数据替换网络请求，观察问题是否消失
- 用桩实现替换第三方 SDK 调用
- 在 Mock 模式下复现原操作路径

**判断逻辑**：
- Mock 后问题消失 → 外部依赖参与了因果链
- Mock 后问题依旧 → 根因在本地逻辑

### 2. 断网隔离（网络时序隔离）

**目标**：排除网络回调时序和网络状态变化的干扰。

**方法**：
- 在飞行模式下执行离线可用的操作路径
- 对比有网和无网环境下的行为差异
- 关注：请求超时回调、网络切换事件、弱网重试

**判断逻辑**：
- 断网后问题消失 → 网络回调时序是因果链一环
- 断网后问题依旧 → 网络不是关键因子

### 3. 缓存隔离（数据层隔离）

**目标**：排除本地缓存/数据库脏数据的干扰。

**方法**：
- 清除应用缓存后复现
- 清除数据库后复现
- 对比首次安装 vs 存量用户的行为差异

**判断逻辑**：
- 清缓存后问题消失 → 缓存不一致是因果链一环
- 清缓存后问题依旧 → 问题不在数据层

### 4. 状态隔离（状态机路径隔离）

**目标**：验证特定状态路径是否是触发异常的必要条件。

**方法**：
- 从已知正常状态出发，仅执行可疑状态转移
- 跳过中间状态，直接进入目标状态（通过调试工具或 DeepLink）
- 对比正常路径和异常路径的状态转移差异

**判断逻辑**：
- 跳过某状态后问题消失 → 该状态转移是因果链一环
- 直接进入目标状态仍有问题 → 问题不在前置路径

### 5. 逻辑隔离（模块级隔离）

**目标**：定位问题所在的具体模块。

**方法**：
- 通过 Feature Flag 禁用可疑模块
- 通过条件编译排除可疑代码路径
- 二分法：依次隔离 50% 可疑模块，缩小范围

**判断逻辑**：
- 禁用模块 X 后问题消失 → 模块 X 参与因果链
- 逐步缩小到具体类/方法

### 6. 时序隔离（并发路径隔离）

**目标**：验证并发时序是否是触发异常的关键因素。

**方法**：
- 将并发操作强制串行化（加锁/单线程 Dispatcher）
- 插入人工延迟（Thread.sleep / DispatchQueue.asyncAfter）改变时序
- 重复执行 N 次观察复现率变化

**判断逻辑**：
- 串行化后问题消失 → 并发时序是根因
- 改变延迟影响复现率 → 竞态窗口大小敏感

## 注意事项

1. **推演 vs 实验**：在代码分析场景下，上述隔离多为"思想实验"（逻辑推演），而非实际操作。推演结论需标注 `[Inferred]`
2. **多因子交互**：单一隔离可能无法发现多因子协同导致的问题。若所有单因子隔离均未定位根因，需考虑因子组合
3. **不可隔离因子**：某些因子（如特定设备固件行为）无法在分析阶段隔离，需标注 `[Non-Isolable]` 并说明原因
