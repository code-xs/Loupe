# Issue Card 模板

```markdown
## Issue Card — {Issue-ID}

### 基本信息
- **ID**: [YYYYMMDD-HHmmss 格式，精确到秒的时间戳，如 20241201-153000]
- **标题**: [平台 模块 具体现象]
- **主分类**: [一级分类] > [二级分类]
- **次分类**: [一级分类] > [二级分类] | 无
- **分类置信度**: High / Medium / Low
- **平台**: Android / iOS / Both
- **优先级**: P0-Critical / P1-High / P2-Medium / P3-Low
- **影响范围**: [用户量估算 / 功能模块 / 版本范围]

### 边界与锚点判定
- **边界等级 (Issue_Boundary_Level)**: EXACT_MR / VERSION_RANGE / HISTORICAL_UNCLEAR
- **边界置信度 (Boundary_Confidence)**: High / Medium / Low
- **备选边界 (Boundary_Alternative)**: [次选边界或无]
- **动态锚点 (Runtime_Anchor_Availability)**: Strong / Weak

### 受理提交物（Intake）
- **判定场景**: interactive（交互式分轮搜集） / document（问题文档或 URL 解析，由系统自动判定）
- **说明**:
  - **document**：用户提交成篇问题描述（全文或 URL），Agent 解析后生成/更新本 Card。
  - **interactive**：用户未交长文档，Agent 按 intake-form 在对话中搜集；本 Card 由多轮信息汇总生成。
- **提交方式**（document 时填写）: 全文粘贴 / 附件文件 / 文档 URL
- **文档 URL**: [若有，可访问链接] | interactive 可填 N/A
- **原始材料存档**: [同目录 `intake-submission.md` 或附录] | 无则 N/A

### 问题描述
- **原始描述**: [用户原话，不做修改]
- **预期效果（Expected Behavior）**: [问题修复后的目标行为]
- **关键信息摘要**: [AI 提取的结构化信息]

### 环境信息
- **APP 版本**: [版本号] | 来源: [用户提供 / APM 自动拉取 / AI 推断[AI-Inferred]]
- **设备型号**: [型号] | 来源: [同上]
- **OS 版本**: [版本号] | 来源: [同上]
- **网络状态**: [WiFi / 4G / 5G / 未知] | 来源: [同上]

### 复现信息
- **可复现性**: 必现 / 偶现 / 仅一次
- **复现路径**: [操作步骤，若有]
- **复现率**: [如有数据]

### 代码与文档上下文
- **仓库路径**: [本地路径或远端 URL] | 必填性: 见 intake-form 按类型 | 缺失则标 [Context-Gap]
- **仓库分支**: [分支名] | 必填性: 通常为选填
- **代码 diff / patch**: [git diff 摘要、附件路径或 `无`] | 已有本地修改时 **必填**
- **需求文档（PRD）**: [链接或文档 ID] | 功能/UI 类见 intake-form **必填**规则
- **技术方案**: [设计文档 / RFC 链接] | 网络/兼容性/安全等见 intake-form **建议必填/必填**规则

### 信息完整度评估
- **信息完整度**: 完整 / 部分缺失
- **缺失项**: [列出缺失的信息项]
- **信息来源汇总**:
  - 用户受理文档[User-Provided]: [文档 URL 或「见附录全文」]
  - 用户提供（其他）: [列出]
  - APM 自动拉取: [列出]
  - AI 推断[AI-Inferred]: [列出]

### 优先级评估依据
| 维度 | 评估 |
|------|------|
| 主流程影响 | [是否阻断主流程] |
| 影响用户量 | [估算百分比或数量] |
| 数据安全 | [是否涉及数据丢失/泄露] |
| 崩溃频率 | [如适用] |

### 工作流状态
- **当前状态**: Spec-Defining / Info-Insufficient
- **创建时间**: [时间戳]
- **最后更新**: [时间戳]
```

## 字段填写说明

| 字段 | 必填 | 说明 |
|------|------|------|
| ID | 是 | 格式 YYYYMMDD-HHmmss，精确到秒以隔离会话 |
| 标题 | 是 | 格式: [平台] [模块] [具体现象] |
| 主分类 | 是 | 从标准分类树选择 |
| 次分类 | 否 | 复合问题时填写 |
| 平台 | 是 | 必须明确 |
| 预期效果（Expected Behavior） | 是 | 修复目标基线，缺失则不能进入 RCA |
| 优先级 | 是 | P0: 主流程阻断/大规模崩溃/数据丢失/安全漏洞；P1: 核心功能受损/>10%用户；P2: 功能可用但体验劣化；P3: 轻微体验问题 |
| 可复现性 | 是 | 必需项 |
| 判定场景 | 自动 | interactive / document，由系统根据是否有问题描述清单自动判定 |
| 仓库路径 | 按类型 | 见 `templates/intake-form.md` |
| 仓库分支 | 通常为否 | 无代码关联时可 N/A |
| 代码 diff / patch | 条件必填 | 已做本地修改时必须提供 |
| 需求文档 | 按类型 | 功能/UI 等见 intake-form |
| 技术方案 | 按类型 | 网络/兼容/安全等见 intake-form |
