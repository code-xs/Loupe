# ADR-004: 审计范围口径双层化

> **状态**：active
> **关联决定**：D4（v1.0 review 拍板，v1.2.1 落地）
> **关联 PR**：v1.2.1 报告修订（已合入）

## 1. 背景

QUALITY-AUDIT-REPORT 多个版本的"审计文件总数"口径不一致：① v1.0/v1.1 笼统说"全部 74 个文件"；② v1.2 改为更精确表述但仍混淆"工作流源码"与"审计文档自身"。需要双层口径标准化。

## 2. 决定

审计范围口径**双层化**：
- **顶层口径**：审计对象 = 工作流源码资产（`core/` + `phases/` + `agents/` + `templates/` + `scripts/` + `functionality-deep-dive/` + 入口文档）
- **排除项**：同目录下后续生成的审计 / 评审 / 施工文档（QUALITY-AUDIT-* 系列、construction-plans/* 系列）
- 报告头部必须显式声明该口径，避免"目录文件总数"与"审计对象数"被等号化

## 3. 替代方案

- **方案 X**（仅按目录文件总数）：被拒绝。理由：会随报告自身的产出而变动，违反"审计对象稳定性"原则。

## 4. 影响

- **报告层**：所有 QUALITY-AUDIT-REPORT-vX.X.md 头部必须含范围口径声明
- **施工层**：QUALITY-AUDIT-CONSTRUCTION-PLAN-vX.X.md 影响计数与该口径绑定
- **后续演进**：v4.3 报告若新增审计对象（如 `eval-cases/`），需在本 ADR 增补一节"v4.3 范围扩展"
