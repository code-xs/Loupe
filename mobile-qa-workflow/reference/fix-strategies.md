# 修复策略知识库与动态 Proposal 路由

## 路由矩阵

| 条件 | Fix Strategy Mode | 角色组合 | 适用场景 |
|------|-------------------|---------|---------|
| 高置信度 + 单点改动 + 低风险 | `single-proposer` | `fix-proposer` | 直接闭环，压低默认成本 |
| 中等置信度 或 中风险 | `challenged-proposer` | `fix-proposer + challenger` | 保留方案攻击，避免误修 |
| 多方案竞争 / 高风险 / P6 回流 | `contested-arbitrated` | `2 proposers + challenger + arbiter` | 对抗式方案收敛 |

## 路由判定建议
- `low risk`：单文件或单模块、无共享状态、无跨平台分歧、可快速回滚
- `medium risk`：影响 2-3 个模块、存在并发或状态恢复路径、需要回归多个入口
- `high risk`：跨端、跨模块、涉及协议/持久化/状态机/并发收敛，或需要大规模回滚保护

## `single-proposer` 约束
- 必须完成四重论证
- 必须给出回滚方案与回归测试设计
- 若在论证中发现未闭合风险，允许升级到 `challenged-proposer`

## `challenged-proposer` 约束
- Challenger 只执行 `fix-4a`
- 若 Challenger 给出 `Critical`，必须升级到 `contested-arbitrated`
- 允许在当前模式下输出“单方案 + 风险清单”结果

## `contested-arbitrated` 约束
- Proposer-B 必须尝试不同策略，不得与 A 仅做措辞差异
- Arbiter 必须输出评估矩阵与最终裁定理由
- 若验证阶段回流，优先复用此模式

## 问题类型修复策略

### Crash / 稳定性
- NPE：优先修空值来源，空检查只能作为补充兜底
- OOM：释放引用链、削峰、限制大对象
- ANR / Freeze：异步化、锁粒度优化、解除主线程阻塞

### 功能类
- 逻辑错误：修缺陷本身 + 补覆盖此路径的测试
- 状态管理：补全状态转换与守卫条件
- 数据一致性：事务化、幂等、冲突检测与重拉
- 异步回调：上下文有效性校验 + 生命周期绑定

### UI / UX
- 布局错位：优先修约束 / 计算逻辑
- 适配问题：安全区、响应式布局、密度资源对齐
- 动画异常：修时序 / 取消路径 / 渲染线程模型
- 复杂 UI 问题：优先回看主 RCA 中的 UI/UX 证据链与布局/渲染/交互时序分析结论

### 网络
- 请求失败：修请求构造或契约漂移
- 超时：调优耗时、重试、弱网体验
- 数据不一致：缓存策略、并发去重、校验修复

### 兼容性
- API 不可用：版本检查 + 兼容实现
- ROM 差异：抽象适配层
- SDK 兼容：升级、锁版、隔离依赖
