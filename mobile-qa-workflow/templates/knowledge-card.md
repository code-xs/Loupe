# Knowledge Card 模板

```markdown
## Knowledge Card — {Issue-ID}

### 元信息
- **关联 Issue**: [Issue Card ID]
- **创建时间**: [时间戳]
- **关联标签**: [平台] [模块] [问题类型] [根因类型]
- **L3-Dynamic 回填状态**: [Pending-CI]

### 边界路由与策展复盘 (Boundary & Curation Effectiveness)
- **边界等级**: [该案例当时的 Issue_Boundary_Level]
- **路由是否有效收缩了搜索空间**: Yes / No
- **典型噪声/策展模式**: [记录在策展阶段发现的相似代码或历史死分支特征，例如 "XX模块存在3个平行实现"]

### 问题模式
[一句话概括这类问题的模式，剥离具体业务名词，便于后续检索匹配]

### 根因模式
[根因的抽象描述，剥离具体业务细节，提炼为可迁移的缺陷类型]

### 修复模式
[修复方案的抽象描述，便于同类问题复用]

### 因果链模板
[触发条件类型] → [中间状态类型] → [最终异常类型]
（从具体实例抽象为模式，供 Strategy-Pattern 匹配使用）

### 预防建议
- [开发阶段如何避免此类问题]
- [Code Review 关注点]
- [测试覆盖建议]

### 检测规则
[可转化为静态分析/Lint 规则的检测建议]
```
伪代码/规则描述:
if [条件模式] then
    warning: [提示信息]
end
```

### L3-Dynamic 回填区
> 待 CI 流水线或真机验证后回填
- **Crash Free Rate**: [Pending-CI → 回填实际值]
- **关键链路性能(P95)**: [Pending-CI → 回填实际值]
- **内存占用**: [Pending-CI → 回填实际值]
- **回填时间**: [待回填]
- **回填人**: [待回填]

### 关键学习
- **最有效策略**: [本次分析中最有效的分析策略是什么]
- **最有价值证据**: [哪条证据对定位根因最关键]
- **分析弯路**: [有哪些分析弯路，如何避免]
- **经验总结**: [一句话总结本次最重要的经验]
```
