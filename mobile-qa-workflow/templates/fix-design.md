# Fix Design Document 模板

```markdown
## Fix Design Document — {Issue-ID}

### 关联信息
- **Root Cause Report ID**: [关联]
- **根因置信度**: [0.XX] ([High/Medium/Low])
- **专项子工作流**: [未触发 / functionality-deep-dive / ui-deep-dive]
- **Fix Strategy Mode**: [single-proposer / challenged-proposer / contested-arbitrated]
- **Fix Risk Level**: [low / medium / high]

### 选定方案概述
- **修复策略**: [策略名称]
- **策略类型**: [治本 / 治标（须说明为什么不选治本）]
- **变更范围**: [文件列表 + 预估变更行数]
- **一句话描述**: [这个修复做什么，为什么这么做]
- **为什么选当前路由**: [为何是单方案 / 质疑增强 / 多方案仲裁]

### 形式化论证

#### 论证 1: 根因覆盖性（Completeness）
- **因果链**: A -> B -> C -> D(异常)
- **本修复切断环节**: ...
- **论证**: ...

#### 论证 2: 副作用安全性（Safety）
- **修改函数/方法**: [函数名]
- **调用者分析**: [关键调用者及影响]
- **共享状态/资源分析**: ...
- **并发场景安全性**: ...
- **平台差异性影响**: ...

#### 论证 3: Spec 一致性（Correctness）
- Expected Behavior 1: ...
- Expected Behavior 2: ...
- Invariant 1: ...
- 边界条件: ...
- 异常路径: ...

#### 论证 4: 最小性（Minimality）
- [为什么这是合理最小变更]
- [不存在更小方案的原因]
- [无搭便车改动]

### 选项记录

#### 选定方案
- **Option ID**: [A / B / Unified]
- **核心差异点**: [...]
- **被挑战后残留风险**: [...]

#### 竞争方案记录（如有）
| Option | 摘要 | 状态 | 未采纳原因 |
|--------|------|------|-----------|
| A | ... | selected / rejected / merged | ... |
| B | ... | ... | ... |

#### 评估矩阵（当模式为 contested-arbitrated 时必填）
| 评估维度 | 权重 | 方案A 评分 | 方案B 评分 | Unified 评分 |
|---------|------|-----------|-----------|-------------|
| 根因覆盖度 | 30% | | | |
| 副作用风险 | 25% | | | |
| 变更最小性 | 15% | | | |
| 跨平台一致性 | 10% | | | |
| 可回滚性 | 10% | | | |
| 长期可维护性 | 10% | | | |

### 跨平台处理
- **Android**: [具体修改内容 + 平台特异性说明]
- **iOS**: [具体修改内容 + 平台特异性说明]
- **一致性评估**:
  - L1-视觉一致性: ...
  - L2-行为一致性: ...
  - L3-容错一致性: ...
- **差异说明**: ...

### 专项附录（按需填写）
- **Functionality Deep-Dive**: [如触发则引用 `deep-dive-summary.md` / `defensive-fix-design.md`]
- **UI Deep-Dive**: [如触发则引用 `ui-deep-dive-summary.md`]

### 回归测试设计
- [TC1] **直接验证**: ...
- [TC2] **边界验证**: ...
- [TC3] **回归验证**: ...
- [TC4] **跨平台验证**: ...
- [TC5] **专项附录验证**: [仅专项触发时填写]

### 回滚方案
- **回滚方式**: [revert commit / feature flag / 配置下发]
- **回滚影响**: [回滚后的已知影响]
- **回滚触发条件**: [什么情况下应该回滚]
```
