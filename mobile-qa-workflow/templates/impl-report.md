# Implementation Report 模板

```markdown
## Implementation Report — {Issue-ID}

### 元信息
- **关联 Issue**: [Issue Card ID]
- **关联 Fix Design**: [Fix Design Document ID]
- **工作分支**: fix/ai-issue-{ID}（无 Git 时标注: 无分支，代码以内联块提供）
- **实施时间**: [开始时间 — 完成时间]
- **Execution-Status**: [Success | Human-Review | Incomplete]
- **Repair-Route**: [code-fix | non-code-fix]

### 变更清单
| 文件路径 | 变更类型 | 变更行数 | 变更摘要 |
|---------|---------|---------|---------|
| [path] | [新增/修改/删除] | [+N/-M] | [一句话描述改了什么] |

### 与 Fix Design 的对照
- **方案一致性**: [完全一致 / 有调整]
- **调整说明**: [如有调整，说明原因和影响]
- **论证更新**: [调整是否影响了四重论证的结论？如有，补充说明]

### 契约溯源记录

> 从 Contract Checklist 汇总。代码修复路径（Repair-Route = code-fix）时必填。

| # | 溯源项 | 源文件 | 期望值 | 实际值 | 匹配状态 |
|---|--------|--------|--------|--------|----------|
| 1 | [API/资源/配置键名称] | [文件路径:行号] | [fix-design 中预期使用的值] | [从源文件实际检索到的值] | ✅/❌+修正动作 |

### 微验证纠错记录

> 当编码实施过程中触发纠错循环时填写。

| 轮次 | 错误摘要 | 报错文件:行号 | 溯源操作 | 修正动作 | 验证结果 |
|------|---------|-------------|---------|---------|---------|
| 1 | [错误描述] | [file:line] | [回溯溯源/检索定义] | [修正内容] | [通过/未通过] |

### 防御性修复实施记录

> 当存在防御性修复设计（来自 Functionality Deep-Dive F5）时填写。

| 条目ID | Priority | 类型 | 实施状态 | 代码位置 | 备注 |
|--------|----------|------|---------|---------|------|
| df-001 | critical | [熔断器/状态断言/防御性守卫] | [已实施/跳过+原因] | [file:line] | [备注] |

### 静态微验证结果
- **验证方式**: [真实 Lint 工具 / AI 代码走查（无工具链）]
- **Lint 工具**: [Android Lint / SwiftLint / 其他 / N/A]
- **检查轮次**: [N 轮通过 / 达到上限触发 Human-Review]
- **Lint Error 数**: [修改前 N → 修改后 M]
- **Lint Warning 新增**: [逐条列出，说明是否可接受]
- **API 版本合规**: [通过 / 存在风险点（列出）]

### 检查清单执行结果
- [ ] 修改符合 Fix Design Document 四重论证
- [ ] 静态 Lint/AST 检查通过（或 AI 代码走查通过）
- [ ] 没有引入新的 Lint Error（Warning 须列出）
- [ ] 添加了必要的防御性代码
- [ ] 异常路径有合理的降级策略
- [ ] 线程安全性已确认
- [ ] 内存管理正确（无泄漏/野指针风险）
- [ ] 跨平台行为一致（L1/L2/L3 评估结果）
- [ ] 添加/更新了相关单元测试

### 测试执行结果
| 测试类型 | 用例数 | 通过 | 失败 | 跳过 | 备注 |
|---------|-------|------|------|------|------|
| 直接验证（修复是否生效） | | | | | |
| 边界验证 | | | | | |
| 回归验证 | | | | | |
| 跨平台验证 | | | | | |

### 残留风险
- [实施过程中发现的新风险或无法在本次修复中解决的关联问题]

### 代码修改详情（无 Git 环境时填写）
> 无 Git 环境时，以完整代码块形式列出每个修改文件的变更内容，注明文件路径和修改位置。

### PR/MR 生成信息（Phase 6 验证通过后填写）
- **PR 标题**: fix: [一句话描述] (issue-{ID})
- **PR 描述**: [自动包含 Root Cause Report 摘要 + Fix Design 摘要 + Verification Report 链接]
- **Reviewer 建议**: [基于变更范围自动推荐相关模块 Owner]
```
